# Application flow

| Flow | Steps | Completion evidence |
| --- | --- | --- |
| Enter scouting | Home → player posters or locker-room entrance → Dashboard | Enter from touch, keyboard and mouse with reduced motion enabled or disabled |
| Discover | Talent Pool → select competition, season and format → apply search and filters → open profile | Profile explains cohort, sample size, source and unavailable data |
| Compare | Shortlist → select candidates → choose a shared cohort → Compare | Side-by-side statistics and trends use the same format, competition and season |
| Recruit | Team Builder → define vacancy and priorities → Recommendations → Decision Lab → report | A weighting change can alter the ranking, and the report shows the evidence behind the result |
| Review footage | Vision Lab → authorize source and upload → job status → annotated output → delete | Track IDs, measurement units, detector information and limitations are visible |
| Submit data | Player or scout signs in → Data Studio → validate upload → preview identity matches → import | Errors identify invalid rows, and authorized records retain provenance |
| Ask an assistant | Enter a scouting question → confirm or apply available context → inspect citations and ranking | Tool-backed results link to the same cohort and evidence used by the UI |

Use task-specific empty and error states. Maintain shortlist and currently selected cohort across profile navigation. Keep login, permission and consent states distinct so the user knows how to continue.
